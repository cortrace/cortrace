# Cortrace — 周期剖析的实测数据汇总
日期：2026-10-30
状态：全部数据来自 STM32H743（Cortex-M7，150 MHz）上的实测，方法和工具见 `08-cycle-profile.md`。
本文把验证数据、两个固件（NuttX、LVGL）的剖析结果和缓存对照放在一处，数字都可以用 §7 的命令复现。
---
## 1. 实验设置
| 项目 | 内容 |
|---|---|
| 目标 | STM32H743，CPU 150 MHz，I-cache 16 KB、D-cache 16 KB，ETMv4，4 位并口 TPIU |
| 采集 | Artix-7 采集器，UDP 回传，每次抓 3 秒（约 2.25 亿字节原始数据，LVGL 为 1.69 亿） |
| ETM | `TRCCONFIGR=0x811`（周期计数 + 时间戳），`TRCCCCTLR=0x10`（周期计数阈值 16），`TRCSTALLCTLR=0x100` |
| DWT | `DWT_CTRL` 打开 CPI、EXC、SLEEP、LSU、FOLD 五个事件计数器和 `SYNCTAP`，每个包代表 256 次事件 |
| 固件 A | NuttX：计算线程（`compute_step`/`compute_mix`）、文件 I/O 线程、内核 note，SysTick 100 Hz；I/D cache 开，D-cache 为**写通** |
| 固件 B | LVGL 9.6 的 `lv_demo_widgets`，480×272 RGB565，每秒强制渲染一整帧，帧间 `WFI`；I/D cache 开，D-cache 为**写回**。§4.1 到 §4.6 是 `-O2`（这个固件的默认值），§4.7 是 `-O3` |
| 缓存开关 | 运行时改 `SCB_CCR` 的 IC（bit17）和 DC（bit16），每种配置从复位重新开始 |

**切换缓存的两个坑。**
- 写通的 D-cache（NuttX）可以直接关。写回的 D-cache（LVGL）直接关会丢掉脏行：实测核心进了 HardFault，帧计数停住，
  周期数恰好等于指令数（CPI 1.000）。要先停核、按组和路对整个 D-cache 做 clean+invalidate（写 `DCCISW`），再改 `CCR`，然后继续运行。
- `reset run` 会清掉 TPIU 的配置，抓取前要重新 `cortrace arm`。

每种配置抓一次，帧数用指令数核对（LVGL 四种配置的指令数在 1628 万到 1636 万之间，相差 0.5%，说明做的是同一份工作）。

## 2. 数据可信度
| 检查 | 结果 |
|---|---|
| 周期时钟对全局时间戳（NuttX，3 s，6 次抓取） | −0.0 到 +8.7 ppm |
| SysTick 间隔对真值 1,500,000 周期 | 中位数偏差 0 到 2 个周期 |
| 重复抓取（NuttX） | CPI 1.469 / 1.468；LVGL 三次 CPI 1.269 / 1.268 / 1.268 |
| 关 `TRCSTALLCTLR`（FIFO 满是否拖住 CPU） | 指令数、CPI 逐项相同，没有反压 |
| 各函数自身周期之和 + 无指令周期 | 等于周期总数（误差 < 1 个周期） |
| 把时间戳包带的周期数也加进时钟 | 多算约 1%（+9720 ppm），SysTick 间隔偏 14,580 周期，所以不加 |
| 周期计数归属（CC 覆盖它之前的指令段） | 关缓存的运行里，窗口周期与窗口自己的指令数相关（r=0.46、0.33），与上一个窗口的相关低得多（0.34、−0.01） |

**DWT 计数器的恒等式。** 七次测量里，下式都成立：

> 周期 = 指令数 − FOLD + CPI + LSU + EXC（计数器各乘 256）

| 运行 | 周期 | 计数器合计 | 差 |
|---|---|---|---|
| NuttX，缓存开 | 450,030,824 | 450,031,832 | +0.00% |
| NuttX，D-cache 关 | 450,021,924 | 450,023,099 | +0.00% |
| 20% 占空的 WFI 程序 | 60,013,150 | 60,014,694 | +0.00% |
| LVGL，缓存开 | 20,772,136 | 20,833,414 | +0.30% |
| LVGL，D-cache 关 | 28,113,187 | 28,172,816 | +0.21% |
| LVGL，I-cache 关 | 38,003,905 | 38,153,896 | +0.39% |
| LVGL，两个都关 | 45,134,490 | 45,282,547 | +0.33% |

含义：每条没被折叠的指令占 1 个周期，其余都是三类额外周期。LSU 是读写的额外周期；EXC 是异常入口和出口；
CPI 是除读写以外的所有停顿，**包括取指停顿**（LVGL 关 I-cache 后 CPI 计数器从 650 万升到 2350 万，增量与周期增量 1720 万几乎相等）。
这个恒等式也是报告里"DWT counters"一行的校验。

**SLEEP 的验证。**
- 只执行 WFI 的循环，2 秒：1,171,962 个 SLEEP 包 ×256 = 3.0 亿周期，等于 150 MHz × 2 s，其他位为 0。
- 20% 占空的程序（忙 30 万周期，睡到下个 1.5M 周期的 SysTick）：忙 6001 万周期 + 睡 2.400 亿 = 3.00002 亿，对墙钟 6 ppm；测得占用率 20.0%。
- **睡眠期间 ETM 的周期计数不走**：这次的周期时钟比时间戳少 79.9%。所以占用率按 忙/(忙+睡) 算，时钟自检要加回两个时间戳之间的睡眠周期。

### 3.2 异常
| 异常 | 次数 | 入口（p50） | 运行（p50 / p99 / max） |
|---|---|---|---|
| SVCall | 29,011 | 54 | 451 / 559 / 583（最小 371） |
| PendSV | 15 | 21 | 347 / 443 / 443 |
| SysTick | 300 | 47 | 289 / 约 3,300 / 约 3,500 |

SysTick 约 5% 的次数要跑调度器，耗时约 3,400 周期，和 PendSV 的 15 次吻合。

### 3.3 中断延迟抖动
300 个 SysTick 对 1,500,000 周期的格子，比最早的一次晚到：p50 18、p90 1,996、p99 3,284、max 3,306 周期（22 µs）。
约 1/6 的 tick 晚到超过 1,000 周期。

原因找到了：晚到的 tick 全部是被 `nxsched_set_running_priority` 屏蔽住的。它提高 BASEPRI，每次实测 2,854 到 3,786 周期（p50 3,421），
3 秒里被调用 28,993 次，屏蔽了 22% 的时间；300 个 tick 里有 70 到 74 个（23% 到 25%）落在这个区间，晚到量在 0 到 3,500 之间均匀分布。

关 D-cache 多出的 16.3 ms/帧里，`argb8888_image_blend` 占 29%（+4.77 ms），纯色填充 20%（+3.24 ms），字体取位图 14%（+2.24 ms），样式属性查找 7%。
关 I-cache 多出的 38.3 ms/帧里，纯色填充一个函数占 35%（+13.44 ms）：它的内层循环块（0802f150）从 32 周期/次变成 76 到 78 周期/次，是缓存命中时的 2.4 倍，每次都要去 Flash 取指。

读出来的结论：
- **D-cache 帮的是读**：字体位图、图片源数据、样式表这些只读数据，关掉后 LSU 占比飙到 50% 到 65%。`lv_memset` 只写帧缓冲，关 D-cache 一点不变（写通/不分配，写本来就不走缓存）。
- **I-cache 帮的是紧循环**：像素循环小而热，命中后 32 周期，不命中时每次都要去 Flash 取指。
- 两者都开，一帧 46 ms；只丢一个，慢 35% 或 83%。
### 4.7 `-O3` 下一帧的周期构成
同一份源码（`make LVGL=1 OPT=-O3`），其余条件不变。先核对做的是同一份工作：`lv_refr_now` 都是 3 次，
`lv_draw_sw_blend_color_to_rgb565` 都是 1530 次，`lv_font_get_bitmap_fmt_txt` 366 次，`lv_memset` 3311 次，调用次数逐项相同
（`argb8888_image_blend` 在 `-O3` 下不再作为独立函数出现，对应的热点是 `lv_draw_sw_blend_image_to_rgb565`，推测被内联了）。渲染出的像素没有逐点比对。

一帧的周期构成（缓存全开，两次抓取一致，周期 = 发射 + 其他停顿 + LSU + 异常，见 §2 的恒等式）：

| 构成 | `-O2` | `-O3` | `-O3` 占比 | 含义 |
|---|---|---|---|---|
| 发射（指令数 − 折叠） | 24.6 ms | **7.7 ms** | **50.5%** | 每条没被折叠的指令 1 个周期，指令开销 |
| 其他停顿（CPI 计数器） | 14.4 ms | **5.5 ms** | **36.2%** | 多周期指令、分支和流水线停顿、取指停顿 |
| 访存（LSU） | 7.2 ms | **1.9 ms** | **12.4%** | 读写指令多花的周期 |
| 异常开销（EXC） | 0.14 ms | 0.13 ms | 0.9% | SysTick 等 |
| 合计 | 46.2 ms | **15.0 ms** | 100% | CPI 1.254（`-O2` 为 1.270） |

占比是把四项归一到 100%（它们加起来是周期的 101.2%，见 §2 的恒等式）。每帧 225 万个周期、179 万条指令（`-O2` 是 692 万、545 万）。
对 CPU：一帧忙 15 ms，占用率 1.5%（`-O2` 是 4.6%）。

要点：
- `-O3` 把一帧从 46.2 ms 缩到 15.0 ms（×0.32），指令数缩到 ×0.33，发射周期缩到 ×0.31，**CPI 几乎没变**（1.270 → 1.254）。
  收益来自指令变少，不是停顿变少。
- 各类的缩小幅度：发射 ×0.31，其他停顿 ×0.38，访存 ×0.26，异常开销不变（×0.98）。访存缩得最多，其他停顿缩得最少，所以其他停顿的占比从 31% 升到 36%。
- 发射周期在四种缓存配置下都是 7.6 到 8.0 ms，因为指令数不变；缓存只改变停顿。

缓存对照（ms/帧，发射 / 其他停顿 / LSU）：

| 配置 | 帧时间 | 相对缓存全开 | 发射 | 其他停顿 | LSU |
|---|---|---|---|---|---|
| I+D 开 | 15.0 | ×1.00 | 7.7 | 5.5 | 1.9 |
| 关 D-cache | 26.9 | ×1.80 | 7.6 | 5.2 | **14.1** |
| 关 I-cache | 38.0 | ×2.53 | 8.0 | **28.7** | 1.3 |
| 两个都关 | 47.6 | ×3.17 | 7.9 | 21.5 | 18.2 |

- 缓存对 `-O3` 更重要：关 D-cache 慢 ×1.80，关 I-cache 慢 ×2.53，全关 ×3.17（`-O2` 是 ×1.35、×1.83、×2.17）。
  指令变少以后，不变的发射周期变小，停顿占的比例就大了。
- **`-O3` 全关缓存（47.6 ms）和 `-O2` 缓存全开（46.2 ms）一样慢**：优化等级和缓存对这个负载的作用大小相当。
- 关 D-cache 多出的 11.9 ms 几乎都在 LSU（+12.2 ms）；关 I-cache 多出的 23.0 ms 几乎都在其他停顿（+23.2 ms），LSU 不变。

"访存开销"怎么算，取决于是否把取指算进去：
- 只算数据读写（LSU）：**12.4%**，约 1.9 ms/帧。
- 把取指停顿也算访存，则上限是 12.4% + 36.2% = 48.6%；其他停顿里取指和流水线各占多少，缓存全开时分不开。
  可以确定的是：关 I-cache 后其他停顿从 5.5 ms 涨到 28.7 ms，说明这部分对取指很敏感。

函数和模块一级的分解在 `-O3` 下更不可靠：函数被内联、变短，事件的位置模糊更明显，按模块分解后三项加起来可以超过 100%
（`misc` 模块是 118%）。整帧一级的数字不受影响（恒等式成立，误差 1.2%）。`-O3` 下最热的两个函数仍是
`lv_draw_sw_blend_color_to_rgb565`（26.2%，3.9 ms/帧，LSU 占其周期的 24%）和 `lv_draw_sw_blend_image_to_rgb565`（17.1%，2.6 ms/帧），
4 个函数占了一半的周期。

## 6. 局限
- 周期计数分辨率 16 个周期；单个函数的周期归属有一个窗口的误差，短函数（几十周期）的 LSU%、其他% 只做参考。
- 事件包的位置由它在 ETM 字节流里的位置决定，而 ETM 把一批分支攒成一个包再发，所以事件可能落在前一个函数里。
  EXC 落点和关 D-cache 的 LSU 对照说明偏差不大，但没有逐函数的真值。
- 每个事件包代表 256 次事件，事件很少的函数抽不到样。
- 睡眠时 ETM 周期计数停走：有睡眠的负载没法测周期性异常的晚到量；时钟自检的睡眠修正误差在 0.01% 量级。
- 每种配置只抓了一次（LVGL 的缓存开配置抓了四次，结果一致）。NuttX 的缓存对照用的是 3 秒的一次抓取。
- LVGL 的帧数按 3 秒约 3 帧估算，并用各配置的指令数核对过。
- 这些结论是这块板、这两个固件、这些链接配置下的数字，不是通用结论。

## 7. 复现
```sh
# 布防：timing profile，五个 DWT 事件计数器全开（SYNCTAP 自动打开）
cortrace arm --platform stm32h743 --os none --profile timing --dwt-events all --probe-telnet 127.0.0.1:4444

# 抓 3 秒并剖析
cortrace profile run --elf fw.elf --out-dir out --iface <nic> --secs 3 --sysclk-hz 150e6 --tsgen-hz 75e6
cortrace profile report out/prof_<tag>.json --top 40

# 缓存对照：改一个条件，再跑一次，对比
cortrace profile diff out/prof_<on>.json out/prof_<off>.json
```
缓存开关（OpenOCD 命令）：
- 写通的 D-cache、或只关 I-cache：`mww 0xE000ED14 <CCR & ~0x20000>`（I-cache），`~0x10000`（D-cache）。
- 写回的 D-cache：先 `halt`，再对 4 路 × 128 组逐个写 `mww 0xE000EF74 [expr {($way << 30) | ($set << 5)}]`（DCCISW），
  然后改 `CCR`，最后 `resume`。
- 恢复：`reset run`（缓存默认开），再 `cortrace arm`。

CPU 空闲率的校验程序是一个几十字节的 Thumb 小程序：SysTick 周期 1,500,000 周期，每个周期里先空转 30 万次，再 `wfi`。
